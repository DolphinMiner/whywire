## Platform

web

## Users

People unfamiliar with a codebase who need to understand the product and its
code organization, follow its main user scenarios, and find the code to read next.

## Product Purpose

Whywire is an Agent Skill. Its project walkthrough produces one standalone HTML
guide with three reading pages: product overview and verified technology stack,
package structure and responsibilities, then scenario request flows with source
entry points.
Small follow-up questions can remain short chat answers.

## Capabilities and Constraints

The user confirmed single HTML delivery on 2026-10-07, then Mermaid diagrams and
separate Overview, Code structure, and Scenarios pages on 2026-10-08. Overview
opens first; ordinary hash links address each page or individual scenario.
Each scenario
has an authored diagram; request flows normally use participant lifelines,
calls, and returns in a sequence diagram.
Preserve source evidence and bounded coverage. A source walkthrough is not a
runtime trace. The guide embeds its Mermaid runtime and works offline;
diagrams require JavaScript in a compatible browser. Without JavaScript, all
pages' text, source references, and native disclosures remain readable. Printing
includes every page. Hosted source links require access. Package and stack
claims need inspected evidence; a missing section is labeled as uncovered.

## Brand Commitments

Keep the Whywire name and existing restrained dark green/orange cover identity.
This is a reading artifact, not a dashboard or architecture editing platform.

## Evidence on Hand

Public Python fixtures are synthetic teaching examples. Private-project test
outputs stay outside this repository. No comparative model-quality or
production-delivery claim has been established.
